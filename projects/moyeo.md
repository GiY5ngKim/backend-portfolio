# MO-YEO

## 1. 프로젝트 개요

대학생과 청년이 관심사 기반 모임을 개설하고, 모집글을 통해 참가자를 모집할 수 있는 서비스입니다.

- 형태: 팀 프로젝트
- 담당: Backend
- Repository: https://github.com/MO-YEO/BE
- 주요 기술: Java, Spring Boot, Spring Data JPA, MySQL, Spring Security, OAuth 2.0, AWS EC2, Nginx

## 2. 담당 기능

- 모집글 생성·조회·수정·삭제
- 모임 지원 및 지원 취소
- 지원자 목록과 지원 상태 조회
- 모집글 북마크
- 게시판 및 댓글
- 모임 후기
- 회원 탈퇴 관련 데이터 정리
- OAuth 2.0 및 CORS 설정
- AWS EC2·Nginx 배포 참여

## 3. 문제 해결 사례 1: 회원 탈퇴 시 외래키 제약 오류

### Problem

회원을 탈퇴시키는 과정에서 해당 회원을 참조하는 지원, 북마크 등의 데이터가 남아 있어 외래키 제약 오류가 발생했습니다.

### Cause

회원 엔티티만 삭제하고 연관 데이터를 먼저 정리하지 않아 데이터베이스 참조 무결성에 위배되었습니다.

### Solution

- 회원을 참조하는 데이터 구조를 확인했습니다.
- 탈퇴 시 먼저 제거해야 하는 연관 데이터의 순서를 정리했습니다.
- `@Modifying`과 JPQL 삭제 쿼리를 사용해 연관 데이터를 일괄 삭제했습니다.
- 이후 회원 엔티티가 삭제되도록 탈퇴 흐름을 수정했습니다.

### Result

회원 탈퇴 시 발생하던 외래키 제약 오류를 해결하고, 탈퇴 로직의 데이터 삭제 순서를 명확하게 만들었습니다.

### Evidence

- [관련 커밋](https://github.com/MO-YEO/BE/commit/49f92a2)

## 4. 문제 해결 사례 2: 목록 조회 시 집계 데이터 처리

### Problem

모집글 목록에서 지원자 수, 북마크 여부 등의 부가 정보를 함께 제공해야 했습니다.

### Approach

각 모집글마다 별도의 조회가 반복되지 않도록 필요한 정보를 한 번에 조회하고 DTO에 매핑하는 방식을 적용했습니다.

### Evidence

- [관련 커밋](https://github.com/MO-YEO/BE/commit/64434e5)

## 5. 아쉬운 점과 개선 계획

- 모집 관련 서비스 클래스의 책임이 커져 기능별 서비스 분리가 필요합니다.
- 권한, 중복 지원, 모집 정원과 같은 핵심 규칙의 자동화 테스트를 보강할 계획입니다.
- 쿼리 수와 실행 시간을 측정해 최적화 결과를 수치로 기록할 계획입니다.
