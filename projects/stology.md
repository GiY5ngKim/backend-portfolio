# Stology

## 1. 프로젝트 개요

사용자의 학습 기록을 기반으로 AI 주간 리포트를 생성하고, 학습 내용 간 관계를 지식 그래프로 제공하는 서비스입니다.

- 형태: 팀 프로젝트
- 담당: Backend
- Repository: https://github.com/Stology/BE
- 주요 기술: Java, Spring Boot, Spring Data JPA, MariaDB, Neo4j, Spring Security, OAuth 2.0

## 2. 담당 기능

- AI 주간 리포트 생성 및 조회
- 리포트 읽음 상태 관리
- 주간 리포트 생성 스케줄러
- MariaDB 학습 데이터와 Neo4j 지식 그래프 연계
- AI 서버 연동용 요청·응답 DTO 구성
- OAuth 로그인 및 토큰 재발급 흐름 개선

## 3. 문제 해결 사례 1: 관계형 데이터와 지식 그래프 연계

### Problem

학습 기록의 기본 정보는 관계형 데이터베이스에 저장하면서, 학습 내용 사이의 연결 관계는 그래프 형태로 표현해야 했습니다.

### Decision

- 사용자, 스터디, 학습 기록 등 정형 데이터는 MariaDB에서 관리했습니다.
- 개념과 개념 사이의 관계는 Neo4j에서 관리했습니다.
- 두 데이터 저장소의 책임을 분리하고 서비스 계층에서 결과를 조합했습니다.

### Result

기존 관계형 데이터 구조를 유지하면서 학습 개념의 연결 관계를 그래프로 제공할 수 있는 구조를 구현했습니다.

### Evidence

- [관련 커밋](https://github.com/Stology/BE/commit/4b7f6a9)

## 4. 문제 해결 사례 2: 주간 리포트 자동 생성

### Problem

사용자가 직접 요청하지 않아도 정해진 주기에 맞춰 학습 리포트를 생성해야 했습니다.

### Solution

- 주 단위 대상 기간을 계산했습니다.
- 리포트 생성 스케줄러를 구현했습니다.
- 생성된 리포트의 읽음 상태를 별도로 관리했습니다.
- API 응답에 필요한 형태로 리포트 데이터를 변환했습니다.

### Evidence

- [관련 커밋](https://github.com/Stology/BE/commit/edca1e8)

## 5. 테스트 및 개선 계획

- 주차 경계 계산 테스트
- 이미 생성된 리포트의 중복 생성 방지 테스트
- 일부 사용자 리포트 생성 실패 시 스케줄러 지속 여부 테스트
- Neo4j 노드 중복 및 누락 상황 테스트
- 환경변수 없이 실행 가능한 테스트 프로필 구성
